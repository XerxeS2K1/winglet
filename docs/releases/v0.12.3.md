# Winglet v0.12.3

A small release. It fixes the web chat's hover toolbar, which vanished as soon as the pointer reached it, and bundles three app changes that were merged after 0.12.2.

## Not tested on a phone

**None of the app changes below that are marked "phone" have been tried on a phone by the owner.** The changes to idle polling and re-rendering, composer drafts and attachment retries have only been checked by unit tests and by GitHub's automated checks (CI). Those tests use a small test harness, not React Native on a device, so they show that the logic behaves as intended and say nothing about how the app feels or looks on a phone. Treat these three as untested on a phone until you have used them.

## Web: the hover toolbar stays open

On the web UI, the Copy / Reply / More toolbar that appears when you hover a message disappeared as soon as the pointer reached it. There were two causes: a button inside the toolbar ended the hover on the message, and the toolbar overhangs its row, where the older row above it painted over it and took the pointer. The toolbar now stays open while the pointer is on it. Only layouts with a mouse are affected; touch and native layouts are unchanged.

This fix was reproduced in headless Chromium on a fixture chat and covered by three new tests. It has not been checked in a live browser, in Firefox or Safari, or when scrolling a long chat. (PR #89)

## Less idle polling and whole-screen re-rendering (phone: not tested)

Several screens kept timers running that did nothing useful, and some redrew a whole screen every second. Each now does the minimum. (PR #86, issues #44, #45, #50, #51, #52)

- The one-second clocks now live in the small parts that print a time, and the link-device expiry redraws once, when it expires.
- Encrypted-push repair no longer restarts when the list of servers changes but the same ones are online, and two repair passes cannot overlap.
- Wear settings start their 3-second poll only when the watch is supported, skip a tick while an action is running, and stop if a later refresh says it is unsupported.
- Routine run detail stops its automatic refreshes once the run has finished.
- The Server screen no longer reruns its focus work on every store update.
- A manual refresh or Retry pressed during a load is queued instead of dropped.

No speed-up is claimed. If a watch becomes supported while you are already on the Wear screen, polling starts after you leave and reopen it.

## Composer drafts are kept until the message is accepted (phone: not tested)

The composer now keeps your text, reply context and ready attachments until the message has entered the outbox (or a signed command has been accepted). If something fails before that point, your draft is still there to retry. Newer text you typed while sending is kept. Joining the outbox is not a promise that the message has reached the server. (PR #87, issue #41)

## No duplicate attachment retry uploads (phone: not tested)

Pressing Retry on a failed attachment repeatedly could start several uploads of the same file. Each file now has one upload attempt at a time, and different files still upload independently. Removing an attachment stops its late progress or completion from bringing it back. Preparing the file may still finish in the background after you remove it. (PR #88, issue #39)

## Upgrading

Update the app from the in-app update, and the plugin from the release zip or `hermes plugins update`. The web UI is served by the plugin, so the hover-toolbar fix reaches it when the plugin is updated. Going from 0.12.2 to 0.12.3 has not been tried through the plugin's self-update yet.
