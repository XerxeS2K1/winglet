# Winglet v0.12.1

A small release: the app stays smoother while several chats stream at once, and a server script can post into a chat.

## Faster while several chats stream

- The app no longer re-checks every old message each time a streamed reply grows.
- A chat that is still streaming is saved to the phone's cache at most every 5 seconds, instead of every second. A finished reply is saved within a second, and leaving the app saves everything straight away.
- This was measured in a Node benchmark on the server, not yet on a phone, so how much you notice on your phone is not proven yet.
- If the app is killed in the middle of a reply, the cached copy on the phone can miss up to the last 5 seconds of that reply. The copy on the server is not affected.

## A script on the server can post into a chat

A local script on the server (for example a scheduled job) can post one bot message into a chat that already exists. It is **off** unless both of these are set: the environment variable `WINGLET_LOCAL_SEND` for the gateway, and `local_send: true` in the Winglet platform's config line. With only one of them, or neither, nothing changes. It never creates a chat.

## For developers

A manual run of the Release workflow can now build a test APK with the developer timing and/or R8 switched on. A release tag or a pull request cannot turn either on, and a manual run started from a branch publishes nothing.

## Upgrading

Update the app from the in-app update, and the plugin from the release zip or `hermes plugins update`. Going from 0.12.0 to 0.12.1 has not been tried through the plugin's self-update yet.
