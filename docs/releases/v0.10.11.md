# Winglet v0.10.11

One tap now updates both halves, the update sheet stops nagging after the install, and the fallback strip says what is actually happening.

- **One tap, one update.** About's Update action used to install the app and only start the server half once you had reopened Winglet — and the Server screen had a second button that started the plugin job on its own, which is why updating both meant two actions in two places. The single action now sends the server plugin job first, then opens the Android installer. The Server screen's Winglet row points at About instead of starting its own job.
- **The order matters, and it is stated plainly.** If you cancel the Android install after the job was sent, the app now says the server plugin was already updated and that this cannot be undone, rather than pretending both were cancelled.
- **A refused start touches nothing.** A 4xx from the server fails the update without opening the installer. A 5xx — the gateway restarting under it — still opens the installer and the job is recovered from history afterwards, so a slow restart does not cost you the update.
- **The update sheet stops coming back.** After Android installed a release, the running process could still be the old build, so the sheet returned saying the new version was "out" on a phone that already had it. An offer that is not newer than the build in front of you is no longer shown, and handing the install to Android clears the offer and its cache.
- **The fallback strip says what is happening.** "Fallback · provider unavailable / next message" is gone. It now reads "Claude rate limited — using GPT-6.1 Sol", with the countdown on the right when the server supplied one and a plain line when it did not, because Hermes does not always send a retry time.

The server plugin is on the same version. Hermes 0.22.7 and 0.23.0 are the supported server versions.

> **Upgrade note.** v0.10.10 can install this release by itself. If you are still on 0.10.5, install the 0.10.8 plugin manually once first; see [SERVER_PLUGIN_UPDATE.md](../SERVER_PLUGIN_UPDATE.md).
