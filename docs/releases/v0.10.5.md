# Winglet v0.10.5

Combined build from the 0.10.4 line plus reviewed feature work. The app and server plugin are now on the same version, and the app can offer to update the server plugin itself.

- **In-app server plugin update.** When the server's plugin is behind the latest release, the app offers "Update server too?" with Update, Later and Skip this version. Only the owner device can trigger it. It asks for a fresh fingerprint or PIN before sending the request. The server installs the release by its commit SHA, makes a backup first, and rolls back automatically if the new version does not start. A failed update never restarts the gateway; it restores files and database and sends a Telegram message. Only newer stable releases are accepted.
- **Queue titles.** Hand-offs can carry a short title shown on the queue sheet instead of the first 120 characters. `ask_bot` takes an optional title; without one it uses the first line cut at about 60 characters.
- **Background activity in the queue.** Bots show as Working while a tracked background process is alive, so a bot running tests no longer looks idle.
- **Fallback notice repair.** The amber fallback strip now appears reliably: the server recognises both the pre-agent and in-turn notice formats and keeps the fallback reason after cache eviction, scoped to the session so reasons never leak across chats.
- **Theme consistency.** All app-owned screens, sheets and pop-ups follow the selected theme, including the battery prompt and the input fields. The bundled web app is rebuilt with the same theme.
- **Release flow on main.** Releases now go through a pull request from integration/dev-all to main, with a tag on main and a release-document check that fails a tag when notes or the README banner are missing or out of date.

No server plugin update is needed beyond installing 0.10.5 itself. Hermes 0.23.0 is still the supported server version.

> **Errata (2026-11-08).** The 0.10.5 server updater omits Hermes's `--yes-deps` consent, so an
> in-app update from this version is refused at the dependency step. A repaired updater is being
> prepared locally and is unreleased; see [SERVER_PLUGIN_UPDATE.md](../SERVER_PLUGIN_UPDATE.md).
