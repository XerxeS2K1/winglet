# Winglet v0.12.4

A performance release. The app no longer freezes for about two seconds each time a message arrives in a long chat, and the developer timing now logs a real launch figure.

## Phone: no more freeze while a reply streams

The app kept a copy of its state on the phone so it could pick up where it left off after a restart. Every incoming message re-encrypted and rewrote the whole copy, up to about 3 MB, on the thread that draws the screen. In a long chat that froze the app for about 2.1 seconds per message.

The copy is now split into a small index and pieces of roughly 64 KB per chat, and a new message writes only the piece that changed. (PR #91)

**Measured on a Samsung Fold 7**, with the same scripted 43-character message and reply, before and after:

- Writing one new message: about 2.15 MB in 1,244 ms, down to about 100 KB in a median 86 ms.
- Longest freeze of the screen: 1,262 ms, down to 159 ms.
- Closing the app and opening it again rewrote only the index and one small piece, not the whole history.

This was one phone, one chat and one scripted run, so treat the numbers as a measurement, not a guarantee. It was also checked by 978 automated tests and a number of independent code reviews.

### What to expect after updating

- **The first launch after updating does a one-time conversion** of your saved history into the new layout. On the test phone it wrote 74 pieces (3.66 MB) in 2.8 seconds. Later launches do not repeat it.
- The conversion is automatic and needs no action. The old copy is removed once the new one is complete.
- Because the saved copy changes shape, going back to 0.12.3 afterwards has not been tested.

## Developer timing: a real launch figure

This only affects the timing build (`EXPO_PUBLIC_WINGLET_PERF=1`); release builds do nothing different. The "cold start" line used to be logged when a chat was first opened by hand, so it measured the wait until you opened a chat, not the launch. It is now taken when the Home screen commits, and the drawn time is a separate line. On the same phone it read 191 to 239 ms after the JavaScript bundle began, over three cold starts. (PR #92)

## Not covered

Nothing visible changes in the app apart from the above. The plugin has no code changes; the bundled web UI is rebuilt from the same app source and looks the same.

## Upgrading

Update the app from the in-app update, and the plugin from the release zip or `hermes plugins update`. Going from 0.12.3 to 0.12.4 has not been tried through the plugin's self-update yet.
