# Winglet v0.10.8

Delivers the unified app+server update flow: one app Update action coordinates both the APK and the matching pinned server-plugin release. No separate auto-update setting, no startup installer, no second server prompt.

- **Unified update flow.** A single user tap triggers both the app APK update and the server plugin update on the selected owner pairing. The server plugin release is pinned to the same version; the updater coordinates both stages in one job pipeline with durable progress, recovery and explicit acknowledgement.
- **Server plugin update is hands-off.** The plugin installs from the release artifact with `--yes-deps` and restarts the gateway automatically — no prompts, no SSH, no manual commands. The app update action manages the whole process.
- **Exact pairing + version pairing.** The server job is created only for the currently selected owner pairing and the requested version. A pairing switch mid-update cancels the send; a lost reply is recovered by version match on history.
- **Recovery hardened.** An orphaned `awaiting-app` record is cleared when the running app version differs, and acknowledged when it matches. Read failures (corrupt/encrypted cache) no longer strand the app — `resetUnreadable` clears the notice and lets a fresh consent overwrite. The 10-minute clock-skew margin for historical job linking is documented.
- **HTTP 5xx → unknown, 4xx → failed.** A proxy 502/504 after the server created the job no longer marks the request as failed with a Done button; it becomes `unknown` so the user can Discard and retry.
- **No redundant prompt.** The redundant first `useEffect` in the host was removed; the single observable effect de-dupes `observe()` calls and prevents the race that could burn consent with a false "failed" notice.
- **Sixth cold-review fixes applied.** All medium and low findings from the sixth independent review resolved: cancel() restores record on write failure and surfaces the error as a notice; `expected` guard on all observe() saves prevents resurrected cancelled notices; offline-close trade-off and clock-skew margin edge cases documented.

The server plugin is on the same version. Hermes 0.22.7 and 0.23.0 are the supported server versions.

> **Upgrade note.** The live 0.10.5 plugin and the published 0.10.6/0.10.7 updaters all omit `--yes-deps`, so none can install this release by itself. A one-time manual install of this release's plugin is required first; see [SERVER_PLUGIN_UPDATE.md](../SERVER_PLUGIN_UPDATE.md).
