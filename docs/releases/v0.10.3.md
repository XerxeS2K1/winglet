# Winglet v0.10.3

Fixes for hands-free voice, the Pet screen and bot activity, plus a visible notice when the model falls back. Tested by the maintainer's automated checks (app type check and tests, plugin tests with and without Hermes) and a separate read-only code review. The new screens have not yet been tried on a phone, so treat this as a release for early adopters. The bot activity fix and the fallback notice need the server plugin updated and the gateway restarted.

- **Hands-free listening can send your speech to the server again.** Expo's `fetch` cannot upload a recording from a file on the phone, and the app reported that as "Can't reach your Hermes server". It now uploads the way hold-to-talk and attachments do.
- **Hands-free errors name the step that failed:** starting the voice session, turning speech into text, or playing the reply.
- **The Codex Pets tab loads.** The Pet screen read the chosen gallery before it was declared, so it always asked Petdex.
- **Bot activity shows for every bot.** The server asked each bot's own folder for its activity, but the one gateway answers from the main folder, so Coder and Research always read "Activity unavailable". (Server plugin update needed.)
- **A fallback strip above the message box** appears while Hermes has switched to a fallback model. It shows the reason (for example rate limit), the model in use, and a countdown to when the main model is tried again. For errors with no cooldown it says "next message". It disappears on its own when the main model is back. (Server plugin update needed.)
- README screenshots are on the default branch.
