# Winglet v0.10.9

Makes the About screen honest: one Update action for whatever is actually behind, whether that is the Android app or only the server plugin.

- **One button, two jobs.** The separate app-update and server-plugin cards are gone. About now offers a single action that updates the app when the app is behind, and updates the server plugin when only the plugin is behind. The label says which one it will do, and to which version, before you tap it.
- **Plugin-only updates are now one tap.** Previously a server-only update told you to go and find a command. It now starts the same hands-off plugin job the app update uses, with the same consent text.
- **No double starts.** The plugin path keeps its own in-flight guard, so a second tap while a job is starting is ignored instead of queuing a second install. It no longer borrows the app flow's working flag, which never tracked plugin jobs.
- **Errors stay where they belong.** A plugin job failure shows its own message; a stale app-update error can no longer appear under the plugin button.
- **The offer refreshes when the job is accepted.** After a successful start the server is re-checked, so a finished update stops advertising itself. A cancelled unlock or a stale pairing leaves the offer in place rather than silently removing it.
- **Version fallback matches the Server screen.** When the release metadata is absent, the button falls back to the legacy latest version instead of refusing to offer the update.

Owners only, as before: the action is disabled for non-owner pairings and never appears for a server that is already current.

The server plugin is on the same version. Hermes 0.22.7 and 0.23.0 are the supported server versions.

> **Upgrade note.** The published 0.10.8 plugin can install this release by itself, so no manual step is needed this time. If you are still on 0.10.5, install the 0.10.8 plugin manually once first; see [SERVER_PLUGIN_UPDATE.md](../SERVER_PLUGIN_UPDATE.md).
